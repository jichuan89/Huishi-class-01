# 数智课堂项目交接（五）

## 数据结构与数据流

更新日期：2026-10-13

本文以当前 TypeScript 类型、Node 数据库 schema、页面状态和保存代码为准。字段随版本演进可能增加；修改前应先以源码类型和 API 校验为准。

## 1. 数据分层和持久化位置

| 数据类别 | 主要结构 | 当前存储位置 | 生命周期 |
|---|---|---|---|
| 用户和权限 | `users` | MySQL | 跨会话持久化 |
| 用户上传模型 | `user_models`、模型文件存储目录 | MySQL 元数据 + 文件系统 | 跨会话持久化，按用户隔离 |
| 教案记录 | `LessonPlan` | `lesson_plans.plan_json` | 用户显式/自动保存后跨会话持久化 |
| 互动课件 | `CoursewareManifest` | `lesson_courseware.manifest` | 保存后跨会话持久化，按 lesson/user 归属 |
| 课堂应用上下文 | `AppliedLessonContext` | `localStorage`，按用户 ID 分区 | 同一浏览器保留；清理浏览器数据会丢失 |
| 课堂侧栏标签 | 字符串 | `localStorage` | 同一浏览器恢复 |
| 当前备课编辑状态 | `FormState`、`LessonPlan`、生成状态 | React state；教案自动保存到服务端 | 页面内状态加服务端记录 |
| 当前模型临时预览 | `blob:` URL、File 对象 | 浏览器内存 | 页面生命周期，不能直接当永久模型地址 |
| 题库和错题 | `QuizQuestion`、错题记录 | 静态题库/服务端错题相关存储 | 题库随代码；错题按用户持久化 |
| 性能遥测 | capture/infer/frame 等记录 | 开发环境内存/控制台接口 | 开发会话，不是业务数据 |

## 2. 用户和权限数据

数据库表：`users`，定义位置：`server/index.js` 初始化 schema 的 `CREATE TABLE`。

| 字段 | 数据库类型 | 可空/默认 | 用途 |
|---|---|---|---|
| `id` | BIGINT UNSIGNED | 自增主键 | 用户内部 ID |
| `username` | VARCHAR(64) | 必填、唯一 | 登录名 |
| `school` | VARCHAR(128) | 可空 | 学校 |
| `display_name` | VARCHAR(64) | 可空 | 展示名称 |
| `avatar_data_url` | MEDIUMTEXT | 可空 | 头像数据 |
| `password_hash` | VARCHAR(255) | 必填 | 密码哈希，不应返回前端 |
| `role` | ENUM(`user`,`admin`) | 默认 `user` | 权限角色 |
| `status` | ENUM(`active`,`disabled`) | 默认 `active` | 账号状态 |
| `created_at` | TIMESTAMP | 当前时间 | 创建时间 |
| `updated_at` | TIMESTAMP | 自动更新 | 修改时间 |
| `last_access_at` | DATETIME | 可空 | 最近访问时间 |
| `last_access_ip` | VARCHAR(45) | 可空 | 最近访问 IP |
| `theme` | VARCHAR(24) | `classic-blue` | 用户主题偏好，初始化时按兼容逻辑补列 |

权限数据流：

```text
Login.tsx
  -> POST /api/auth/login 或 /api/auth/register
  -> Node 校验账号并设置认证 Cookie
  -> App 保存公开用户对象
  -> 页面按 role 选择 Dashboard 或 AdminUsers
```

客户端用户对象不应包含 `password_hash`、JWT secret 或认证凭证明文。

## 6. WarmupQuestion 预热题

定义位置：`services/quizData.ts`。

`WarmupQuestion` 扩展 `QuizQuestion`：

| 字段 | 类型 | 来源/用途 |

## 7. ClassroomModelAsset 模型引用

定义位置：`types/courseware.ts`。

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `source` | `'imported' \| 'generated'` | 是 | 导入模型或生成模型 |
| `localModelId` | string | 否 | 本地模型库记录 ID |
| `modelUrl` | string | 是 | 课堂加载地址 |
| `modelType` | `ModelType` | 是 | `glb/gltf/fbx` |
| `assetUrls` | `Record<string,string>` | 否 | GLTF 贴图/附属资源地址 |
| `fileName` | string | 否 | 模型文件名 |
| `previewImageUrl` | string | 否 | 预览图地址 |

重要约束：

- 浏览器 `blob:` URL 只在当前页面内有效，不是可持久化 URL。
- 应用到课堂时优先使用可由 Node 静态文件服务访问的地址。
- 导入模型只保证外观加载，不自动具备语义部件拆解数据。
- 模型切换后，如果课件绑定的模型 ID/地址不再匹配，应丢弃或重新绑定课件。

## 9. 数据库表和持久化字段

### 9.1 lesson_plans 教案

表结构位于 `server/index.js`：

| 列 | 类型 | 说明 |
|---|---|---|
| `id` | VARCHAR(64) | 教案 ID |
| `user_id` | BIGINT UNSIGNED | 所属用户 |
| `title` | VARCHAR(180) | 列表标题 |
| `subject` | VARCHAR(64) | 从 `plan.request.subject` 冗余提取 |
| `grade` | VARCHAR(64) | 从 `plan.request.grade` 冗余提取 |
| `plan_json` | JSON | 完整 LessonPlan |
| `created_at` | TIMESTAMP | 创建时间 |
| `updated_at` | TIMESTAMP | 自动更新时间 |

主键为 `(id,user_id)`。`GET /api/lesson-plans` 只返回当前用户最近 100 条；前端自动保存记录列表最多保留 30 条 UI 项，但数据库仍按服务端记录处理。

### 9.2 lesson_courseware 互动课件

| 列 | 类型 | 说明 |
|---|---|---|
| `lesson_id` | VARCHAR(64) | 教案 ID |
| `user_id` | BIGINT UNSIGNED | 所属用户 |
| `manifest` | JSON | 完整 CoursewareManifest |
| `revision` | INT UNSIGNED | 版本号，至少为 1 |
| `status` | VARCHAR(24) | `draft` 或其他课件状态 |
| `created_at` | TIMESTAMP | 创建时间 |
| `updated_at` | TIMESTAMP | 自动更新时间 |

主键为 `(lesson_id,user_id)`，课件读写都必须检查当前用户所有权。

### 9.3 用户模型相关表

核心表包括 `user_models` 和 `user_model_jobs`：

- `user_models` 保存用户模型记录和状态。
- `user_model_jobs` 保存异步模型任务 ID、用户 ID、模式和任务状态。
- 实际模型和上传源文件保存在服务端模型存储目录；表内引用文件名/存储标识。
- 重新处理任务依赖保留的源图文件；旧模型缺少参考图时可能不能重新生成。

资源库另由 `resource_tags`、`resource_models`、`resource_model_files` 记录共享资源、标签和文件索引。

### 9.4 反馈及附件

- `user_feedback`：反馈 ID、用户 ID、文本内容、创建时间。
- `feedback_attachments`：反馈 ID、原文件名、随机存储名、MIME 类型、字节数、创建时间。
- 附件二进制存储在文件系统，数据库保存索引和归属关系。

### 9.5 用户语音偏好

`user_voice_preferences` 以 `user_id` 为主键，记录：

- `mode`：`system` 或 `volcengine`。
- `system_voice_uri`：系统语音标识。
- `provider_voice_id`：服务商语音 ID。
- `updated_at`：更新时间。

## 10. localStorage 数据

### 10.1 当前备课旧记录迁移

旧 key：

```text
teacher-studio.records.v1
```

打开备课时，若存在旧格式记录且 `${recordKey}.migrated` 不为 `1`，会调用 `/api/lesson-plans/import-local` 导入，成功后写入迁移标记。不要在迁移完成前随意删除旧 key。

### 10.2 课堂侧栏标签

key：

```text
classroom.sidebar-tab.v1:<userId>
```

按用户保存当前侧栏标签，属于 UI 偏好而非教案业务内容。

### 10.3 已应用课程上下文

key：

```text
classroom.applied-lesson.v1:<userId>
```

存储 `AppliedLessonContext`：

| 字段 | 类型 | 用途 |
|---|---|---|
| `modelUrl` | string，可选 | 课堂模型地址 |
| `localModelId` | string，可选 | 用户模型库 ID |
| `modelType` | `ModelType`，可选 | 模型格式 |
| `assetUrls` | string map，可选 | 附属资源地址 |
| `fileName` | string，可选 | 课堂模型显示名 |
| `warmupQuestions` | `WarmupQuestion[]` | 已启用的课堂预热题 |
| `courseware` | `CoursewareManifest \| null` | 当前课件 |

注意：AppliedLessonContext 不保存完整教案对象；教案本体在 `lesson_plans`。localStorage 只在当前浏览器有效，不替代服务端备份。

## 11. 端到端数据流

### 11.1 生成教案

```text
PrepStudio FormState
  -> formToPayload（数字、数组归一化）
  -> POST /api/prep/lesson-design/generate-draft
  -> Node 认证和代理
  -> Python lesson_design / Ollama adapter
  -> LessonPlan + generation 来源 + designWorkflow
  -> PrepStudio React state
  -> 延迟约 1.5 秒自动调用 POST /api/lesson-plans
  -> MySQL lesson_plans.plan_json
```

Ollama 不可用或输出校验失败时，Python 返回模板回退内容及 `generation.engine='builtin-template'`；页面应保留来源标记。

### 11.2 编辑并确认教案

```text
教师编辑某步骤
  -> DesignStep.data 更新、source=teacher-edited
  -> 受影响下游步骤 status=stale、approved=false
  -> qualityPending=true
  -> 保存并校验
  -> 后端校验 quality/blocking
  -> 教师逐步批准
  -> workflow.status=approved
  -> 允许成稿/导出
```

### 11.3 生成和保存课件

```text
LessonPlan + ClassroomModelAsset + WarmupQuestion[]
  -> POST /api/prep/courseware/generate
  -> Python courseware 生成 CoursewareManifest
  -> 故事板编辑 scenes
  -> POST/PUT 保存
  -> Node 校验 lessonId 和用户归属
  -> MySQL lesson_courseware.manifest
```

编辑场景会增加 `revision` 并设置 `status='draft'`。导出 PPTX 前先检查或生成模型四视图，再导出；模型四视图缺失或不完整时导出应失败，不应静默使用过期图片。

### 11.4 应用到课堂

```text
PrepStudio
  -> 校验启用题
  -> 心脏课程按需生成/取得课件
  -> 组装 ClassroomModelAsset
  -> onApplyLesson(plan, modelUrl, questions, manifest, asset)
  -> Dashboard 过滤 enabled=true 的题目
  -> 课件模型 URL 与当前模型地址同步
  -> 写入 localStorage AppliedLessonContext
  -> 设置 workspaceMode=classroom
  -> 加载模型/课件/课堂题目
```

如果有模型 URL，Dashboard 将模型设为当前舞台内容，并打开摄像头手势；如果只有课件，则进入互动课件内容；两者都没有时清理本地模型并留在课堂。

## 12. 数据生命周期和注意事项

1. `FormState` 是输入快照；生成后保存在 `LessonPlan.request` 中，用于记录和表单恢复。
2. `LessonPlan` JSON 是业务主记录；列表列 `title/subject/grade` 是便于查询的冗余字段，更新时必须与 JSON 同步。
3. `CoursewareManifest` 有独立表和 revision，不应只保存在组件局部 state 后就认为已持久化。
4. 模型 `blob:` URL 是临时预览地址；保存或导出需要服务端可访问地址。
5. 教师修改后的内容需要保留 `source='teacher-edited'`，AI 重生成不应静默覆盖人工编辑。
6. `enabled=false` 的题目/场景不进入课堂运行时，但仍可保留在编辑数据中。
7. 课件绑定模型。如果切换到不匹配模型，必须清除课件或显式重绑定。
8. `qualityPending`、`staleSteps`、未批准步骤是实际审核状态，不能仅凭存在 `LessonPlan` 就认为可导出。
9. 用户、课件和教案读写必须按 `user_id` 做所有权隔离。
10. 用户上传图片、模型和数据库内容属于业务数据，不应复制到公开交接材料。
