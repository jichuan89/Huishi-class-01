# 数智课堂项目交接（三）

## 页面与路由交接

更新日期：2026-10-13

## 1. 路由总体规则

当前前端没有使用 React Router，页面由 `App.tsx` 根据 `window.location.pathname` 和内部状态渲染。

### 1.1 公开页面路径

| 路径 | 页面标识 | 实际组件 | 是否需要登录 |
|---|---|---|---|
| `/` | 首页 | `Landing.tsx` | 否 |
| `/solutions` | 解决方案 | `Landing.tsx` | 否 |
| `/cases` | 案例 | `Landing.tsx` | 否 |
| `/pricing` | 价格 | `Landing.tsx` | 否 |
| `/docs` | 文档 | `Landing.tsx` | 否 |
| `/join` | 加入/联系 | `Landing.tsx` | 否 |

这些页面共用 `Landing` 组件，通过 `MarketingPage` 参数决定当前内容。导航时使用 `history.pushState`，不是页面刷新跳转。

### 1.2 登录后的内部页面

| 内部视图 | 实际组件 | 进入条件 | 离开方式 |
|---|---|---|---|
| `login` | `Login.tsx` | 未登录用户从首页点击进入 | 登录成功、返回首页 |
| `dashboard` | `Dashboard.tsx` | 普通用户登录成功；管理员也可以进入 | 退出登录、返回首页、进入管理页 |
| `admin` | `AdminUsers.tsx` | `user.role === 'admin'` | 进入课堂、退出登录 |

登录后的这些视图主要由 `App` 内的 `view` 状态控制，地址栏通常不会随内部视图变化。

## 2. 应用初始化和登录恢复

入口文件：`index.tsx`。

初始化顺序：

1. 读取 `#root` 节点。
2. 开发环境注销旧 Service Worker 并清理 3D 资源缓存。
3. 生产环境注册 `/sw.js`。
4. 挂载 `ThemeProvider`。
5. 渲染 `App`。
6. `App` 请求 `/api/auth/me` 恢复登录状态。
7. 请求期间显示“正在恢复登录状态”。
8. 请求成功后根据角色进入管理员页或课堂页。
9. 请求失败时进入首页，并保持未登录状态。

关键文件：

- `index.tsx`
- `App.tsx`
- `components/ThemeProvider.tsx`

## 3. 首页和公开营销页面

文件：`Landing.tsx`。

页面入口：

- 直接访问 `/`。
- 访问 `/solutions`、`/cases`、`/pricing`、`/docs`、`/join`。
- 未登录状态下从课堂或登录页返回。

主要页面区域：

1. 顶部导航：品牌、公开页面导航、进入工作台入口。
2. 首屏区域：产品定位、3D 教学场景和进入操作。
3. 解决方案区域：课堂、模型、备课、AI 等能力介绍。
4. 案例区域：教学场景或案例卡片。
5. 文档区域：产品说明弹窗或说明内容。
6. 底部入口：再次进入工作台或切换公开页面。

页面行为：

- 点击公开导航时调用 `onNavigate(page)`。
- 点击进入工作台时调用 `onEnter()`。
- 已登录用户直接进入课堂或管理员页。
- 未登录用户进入登录页。
- 浏览器后退触发 `popstate`，恢复公开页面视图。

## 4. 登录和注册页面

文件：`Login.tsx`。

入口：

- 未登录用户从首页点击进入工作台。
- `App` 的 `view` 为 `login`。

页面模式：

| 模式 | 主要字段 | 提交接口 | 成功后 |
|---|---|---|---|
| 登录 | 用户名、密码 | `/api/auth/login` | 进入课堂或管理员页 |
| 注册 | 用户名、密码、确认密码、学校 | `/api/auth/register` | 使用返回用户身份进入系统 |
| 管理员登录 | 管理员账号和密码 | 登录接口按服务端角色判断 | 进入管理员页 |

页面主要区域：

- 左侧产品介绍区域：大屏显示，移动端隐藏或压缩。
- 右侧认证卡片：模式切换、输入表单、密码显示切换、错误提示。
- 返回入口：调用 `onBack()` 回到首页。

登录成功后，`Login` 调用 `onAuthenticated(data.user)`，由 `App` 保存用户对象并根据 `role` 设置内部视图。

## 5. 主课堂工作台

文件：`Dashboard.tsx`。

进入条件：`App` 中存在已登录的 `user`，且 `view === 'dashboard'`。

### 5.1 顶部工作区切换

`Dashboard` 的主工作区状态：

```ts
type WorkspaceMode = 'classroom' | 'prep' | 'modeling'
```

| 工作区 | 显示内容 | 进入方式 |
|---|---|---|
| `classroom` | 课堂模型、课件、侧栏、课堂控制 | 默认进入 |
| `prep` | 综合备课工作台 | 点击主工作区的备课标签或应用入口 |
| `modeling` | 3D 建模工作区 | 从课堂侧栏或模型相关操作进入 |

### 5.2 课堂页面区域

1. 顶部栏：当前课程/模型状态、工作区切换、用户菜单。
2. 左侧模型资源区：内置模型、我的模型、资源库入口。
3. 中央 3D 舞台：模型查看、旋转、缩放、拆解、标签和课件运行时。
4. 右侧详情区：模型信息、知识讲解、结构图片、课堂辅助内容。
5. 底部或浮层控制区：摄像头、语音、小智、测验和反馈入口。
6. 课堂课件区：当存在 `classCourseware` 时显示互动课件运行时。

### 5.3 课堂主要内容状态

| 状态 | 类型/取值 | 作用 |
|---|---|---|
| `activeContent` | `model / biodigital / interactive` | 中央舞台显示模型、数字人体或互动课件 |
| `modelUrl` | `string \| null` | 当前加载的模型地址 |
| `modelType` | `glb / gltf / fbx` | 当前模型格式 |
| `cameraActive` | boolean | 摄像头手势是否启用 |
| `quizMode` | boolean | 是否进入课堂答题 |
| `classCourseware` | `CoursewareManifest \| null` | 当前应用到课堂的互动课件 |
| `isSidebarCollapsed` | boolean | 左侧资源区是否折叠 |
| `detailPanelOpen` | boolean | 右侧详情区是否打开 |

### 5.4 课堂离开和数据清理规则

- 切换到不同内置模型时，不复用不属于该模型的课件。
- 课件绑定一份教案和一个模型。
- 应用新课程时会更新当前教案、模型、预热题和课件。
- 退出登录时清除当前用户、当前本地模型和课堂视图状态。
- 返回首页不会删除数据库中的教案、模型或课堂记录。

## 6. 综合备课工作台

外层入口：`Dashboard.tsx` 的 `workspaceMode === 'prep'`。

挂载组件：`prep/IntegratedPrepStudio.tsx`。

`IntegratedPrepStudio` 的职责是：

- 在课堂工作台中嵌入 `PrepStudio`。
- 使用 Shadow Root 隔离备课 CSS。
- 注入 `prep-styles.css` 和 `prep-biomed.css`。
- 隐藏独立备课页侧栏，适配课堂内嵌布局。
- 接收 `userId`。
- 通过 `onApplyLesson` 将教案、模型、题目和课件返回给 `Dashboard`。

核心回调：

```text
onBack()
  -> Dashboard 回到 classroom

onApplyLesson(lesson, modelUrl, warmupQuestions, courseware, modelAsset)
  -> Dashboard 保存课堂上下文并加载模型/题目/课件
```

## 7. 备课页面内部阶段

文件：`prep/PrepStudio.tsx`。

备课工作台的主阶段状态：

```ts
type WorkbenchStage = 'model' | 'lesson' | 'output'
```

| 阶段 | 主要内容 | 典型进入条件 |
|---|---|---|
| `model` | 导入或生成 3D 模型 | 新建课程、点击模型准备 |
| `lesson` | 填写课程请求、生成或编辑教案 | 默认备课阶段 |
| `output` | 查看生成结果和后续标签页 | 教案生成成功 |

### 7.1 备课页面左侧或顶部工作区

- 新建课程和示例课程入口。
- 已保存教案记录。
- 搜索和打开历史记录。
- 返回课堂入口。
- 当前课程标题和保存状态。

### 7.2 教案输入阶段

输入内容包括：

- 学段。
- 年级。
- 学科。
- 课题。
- 课型。
- 节数。
- 总时长。
- 班级人数。
- 学生能力层次。
- 学习情境。
- 教学目标。
- 教学重点和难点。
- 教学方法。
- 教材、章节、已有知识、核心问题和考试要点。

具体字段类型、默认值和显示条件在第 4 份文档详细记录。

### 7.3 生成结果标签页

教案生成后，`LessonPreview` 区域包含以下标签：

| 标签 | 内容组件 | 数据依赖 |
|---|---|---|
| `lesson` | 教案预览或本科七步设计 | `draft`、`designWorkflow` |
| `courseware` | `CoursewareStoryboard` | `coursewareManifest` |
| `slides` | PPT 大纲和页编辑 | `draft.slides` |
| `materials` | 教材依据和资料摘录 | `draft.request` |
| `model` | 3D 模型生成/导入和预览 | `modelAsset`、`modelUrl` |
| `warmup` | 五道预热题编辑器 | `warmupQuestions` |
| `export` | `LessonExportPage` | 教案草稿和审核结果 |

标签页不是独立浏览器路由，刷新页面后是否保留取决于当前备课状态和保存逻辑。

## 8. 本科生物医学教案设计页

文件：`prep/UndergraduateDesignWorkflow.tsx`。

该页面嵌在备课结果的 `lesson` 标签中，不是独立 URL。

页面内容：

1. 生成来源提示：Ollama 生成或模板回退。
2. 七步流程导航。
3. 当前步骤内容编辑区。
4. 保存并校验、重做本步、恢复系统版按钮。
5. 当前步骤确认和继续按钮。
6. 质检状态和下游步骤失效提示。
7. 全部确认后进入正式教案或导出流程。

页面限制：

- 引导模式下必须按顺序确认步骤。
- 修改前置步骤会把下游步骤标记为 `stale`。
- `qualityPending` 为真时表示修改后尚未重新校验。
- 所有步骤确认且质量校验通过后，才允许生成正式教案。

## 9. 互动课件故事板页

文件：`prep/CoursewareStoryboard.tsx`。

入口：备课结果的“互动课件”标签。

页面区域：

- 顶部工具栏：桌面/移动预览、恢复系统版、保存、PPTX 导出、离线课件导出。
- 左侧场景轨道：场景序号、标题、布局和启用状态。
- 中央预览区：当前场景的模型或图形预览。
- 场景操作区：前移、后移、启用/停用、重做本场景、课堂预览。
- 右侧或下方编辑区：标题、教学主张、学生操作、预期产出、教学细节和补救内容。

课堂运行时组件：`components/InteractiveCourseware.tsx`。

运行时入口：课堂页面中存在 `classCourseware` 时，由 `Dashboard` 显示互动课件。

## 10. 教案导出页

文件：`prep/LessonExportPage.tsx`。

入口：备课结果标签中的 `export` 状态；通常在教案确认或模型资产准备完成后进入。

页面模式：

| 模式 | 内容 | 导出条件 |
|---|---|---|
| 普通教案 | 教案纸张预览 | 不处于编辑状态且教案可导出 |
| 本科教师版 | AI 成稿、质量检查和教师审核 | AI 审核稿有效、教师确认、没有继续编辑 |

主要操作：

- 返回教案。
- 编辑成稿。
- 完成修改。
- 确认审核。
- 导出 Word。
- AI 成稿失败时重试。

## 11. 管理员页面

文件：`AdminUsers.tsx`。

进入条件：`currentUser.role === 'admin'`。

顶部页面操作：

- 进入课堂。
- 刷新数据。
- 退出登录。

管理标签：

| 标签 | 主要内容 |
|---|---|
| `users` | 用户列表、角色修改、启用/停用、用户日志入口 |
| `logs` | 用户活动日志和分页 |
| `resources` | 资源库管理入口或资源数据 |
| `feedback` | 用户反馈、附件和分页处理 |

资源库组件：`AdminResourceLibrary.tsx`。

资源库涉及模型上传、名称编辑、标签选择、标签新建、模型删除和资源状态管理。

## 12. 页面跳转关系

```text
首页 Landing
  -> 未登录：Login
       -> 普通用户：Dashboard / classroom
       -> 管理员：AdminUsers

Dashboard / classroom
  -> Dashboard / prep
       -> PrepStudio / model
       -> PrepStudio / lesson
       -> PrepStudio / output
            -> lesson
            -> courseware
            -> slides
            -> materials
            -> model
            -> warmup
            -> export
  -> Dashboard / modeling
  -> Dashboard / classroom / InteractiveCourseware

AdminUsers
  -> Dashboard / classroom
  -> AdminResourceLibrary 相关管理区域
```

## 13. 交接时需要特别注意

- 只有公开营销页使用浏览器路径；登录后大多数页面是内部状态，不要仅通过地址栏判断当前页面。
- `IntegratedPrepStudio` 使用 Shadow Root，修改备课样式时要同时检查 `prep-styles.css`、`prep-biomed.css` 和宿主容器样式。
- `CoursewareManifest` 与当前模型绑定，切换模型后不能继续使用不匹配的课件。
- 教案修改后可能触发 `qualityPending`、`stale` 和未批准状态，不能直接认为可以导出。
- 课堂应用入口会把教案、模型、预热题和课件一起传给 `Dashboard`。
- 页面具体控件参数和默认值不在本文件展开，统一记录在 `04-UI参数与交互规则.md`。
