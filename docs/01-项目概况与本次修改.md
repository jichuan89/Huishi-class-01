## 1. 项目定位

本项目是一个面向教师备课和课堂授课的“数智课堂”系统，核心目标是把教案设计、教学课件、3D 教学模型、课堂互动和课后数据连接起来。

系统当前包含两条主要业务链路：

```text
教师备课
  -> 教案设计
  -> 预热题编辑
  -> 3D 模型生成或导入
  -> 互动课件故事板编辑
  -> Word/PPTX/离线 ZIP 导出
  -> 应用到课堂

教师授课
  -> 加载教案、模型、题目和课件
  -> 鼠标/触控/语音/摄像头手势操作
  -> 3D 模型旋转、缩放、拆解和标注
  -> 课堂测验与即时反馈
  -> 记录课堂过程和学习结果
```

## 3. 本次修改的主要范围

### 3.1 课堂手势控制与 3D 交互

本次对课堂端的摄像头手势链路进行了完整优化，涉及：

- 使用 Worker 执行 HandLandmarker 推理，减少主线程阻塞。
- 摄像头采集使用 `requestVideoFrameCallback`，不支持时回退到 `requestAnimationFrame`。
- 控制结果队列最多保留最新结果，避免旧帧堆积。
- 对漏检、短暂姿态误判和 handedness 翻转增加连续性处理。
- 旋转速度和缩放速度统一按“每秒速度”计算，再按渲染帧 `delta` 积分。
- 右手负责旋转和拖动，左手负责缩放，课堂答题时复用摄像头链路。
- 旋转、缩放和拖拽增加时间感知滤波、死区和释放宽限。
- 增加 Worker 无结果 watchdog，超时后清理旧控制状态。
- 模式切换和异常退出时释放 Worker 与摄像头资源。

主要文件：

- `components/HandController.tsx`
- `Dashboard.tsx`
- `components/ModelViewer.tsx`
- `services/handGestureMath.ts`
- `services/performanceTelemetry.ts`

### 3.2 连续拆解和拖拽行为修复

解决了连续拆解时已经释放的旧零件可能被下一次操作再次拖走的问题。

当前规则是：

1. 一次新的捏合只选择一个目标零件。
2. 松开手指后立即固定当前零件位置。
3. 必须在新目标上重新捏合，才允许抓取新的零件。
4. 旋转中断拖拽后，需要完整松开再重新捏合。
5. 精确网格射线命中优先于代理包围盒命中。
6. 不可拆解的核心部件不进入可抓取集合。

主要文件：

- `components/ModelViewer.tsx`
- `components/HandController.tsx`
- `services/handGestureMath.ts`

### 3.3 3D 模型性能和 LOD

本次加入和接入互动 LOD，主要目标是在普通集成显卡设备上保持课堂操作流畅。

主要修改包括：

- 心脏模型接入互动 LOD。
- HIV 和其他高面数器官接入互动 LOD。
- 保留原始高精度模型，用于需要高质量展示的场景。
- 交互期间降低渲染负载，空闲后恢复渲染质量。
- 根据设备物理 DPR 限制交互 DPR 和稳定 DPR。
- 减少高模实时投影阴影开销。
- 对虚拟手使用实例化网格和线段渲染。
- 增加模型模板缓存、引用计数和资源清理，降低模型切换后的 GPU/纹理泄漏风险。

主要资源和文件：

- `public/models/heart-interactive-lod.glb`
- `public/models/heart-anatomy-v1.glb`
- `components/ModelViewer.tsx`
- `components/IntegratedModelingStudio.tsx`
- `scripts/generate-interactive-lod.mjs`

### 3.5 本科生物医学七步教案设计

新增本科生物医学课程的结构化教案设计流程，支持：

- 按步骤生成教案草稿。
- 单独重新生成某一步。
- 编辑当前步骤。
- 修改前置步骤后，将受影响的下游步骤标记为 `stale`。
- 保存并校验当前步骤。
- 教师逐步确认内容。
- 全部步骤通过审核后生成正式教案。
- 使用本地 Ollama 生成具体教学文案。
- Ollama 不可用或结构化结果校验失败时使用模板回退。
